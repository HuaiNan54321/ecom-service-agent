前面七期小夕能查订单、调工具、检索知识库、多 Agent 协作、还有记忆了。但退货流程每次全靠模型临场发挥，有时候忘了查退货政策就直接退款了，步骤顺序全看心情

这期加 Skill，聊两个点



## Skill 到底是什么

Tool 是操作能力，查订单、退款、搜商品，一个 Tool 干一件事。但退货这件事得先查单、看状态能不能退、检索政策确认运费谁承担、最后才退款。这套流程全靠模型在 ReAct 里自由发挥，步骤可能对也可能乱

那把流程写进 system prompt 呢？退货流程 1000 字，订单跟踪 800 字，商品推荐 900 字，全塞进去 3000 字打底，大多数对话根本用不上，白占上下文

Skill 就是解决这个问题的。Anthropic 搞了个 Agent Skills 开放标准，核心思路叫渐进式披露：启动时只加载每个 Skill 的名字和一句话描述，三个加一起不到 200 token。模型判断用户要退货了，再把退货流程的完整指令拉进上下文，按指令走

说白了 Tool 是手里的扳手，Skill 是操作手册。没手册你也能拧螺丝，有手册每次都按标准流程拧，不漏步骤



## 为什么不直接写代码把流程固定死

退货流程固定的话，写个函数按顺序调不就完了，代码写死最稳定

用户说"帮我退货，订单号 ORD-001"，确实可以一条线走完。但用户说"我那个鞋子不太合适，你看怎么处理比较好"，模型得先理解意图、安抚情绪、追问细节，写几个 if-else 搞不定

Skill 是用自然语言写的流程指引，模型读完之后还是用 ReAct 循环和已有工具执行。标准情况按流程走，模糊情况模型自己判断。不是放任自由发挥，也不是代码替代模型，是给模型一个标准作业流程

面试被问"怎么保证 Agent 输出质量稳定"，讲清楚这个设计比背概念管用
